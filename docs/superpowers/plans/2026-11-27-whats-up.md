# What's up ? Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `whats-up` skill in osho-core: a framework-agnostic release-notes window copied into any app, a guard (git pre-push + Claude hook) that asks for a note before production, and the two procedures (install, prepare a release).

**Architecture:** Everything a target repo runs is copied into it at install time (`whats-up.js` into its served folder, `garde.py` into `.whatsup/`), so nothing in the repo depends on the plugin cache path. The plugin keeps the sources, the skill procedures, the writer brief, and a Claude `PreToolUse` relay that calls the repo's own `.whatsup/garde.py` for `gh pr create`.

**Tech Stack:** Python 3 stdlib (guard), vanilla ES module + Shadow DOM (component), bash (relay, tests), node ≥ 18 for the component's self-test (no npm dependency).

**Spec:** `docs/superpowers/specs/2026-11-27-whats-up-design.md`

## Global Constraints

- Public repo: no private app name nor home path in any tracked file, plans included (CI step 7, list in `scripts/ci.sh`).
- No dependency: Python stdlib only; JS without npm packages, bundler or framework.
- Note id: `YYYY-MM-DD`, then `-2`, `-3`… the same day; order = (date, suffix as integer, none = 1).
- Theme variables: `--wu-fond`, `--wu-texte`, `--wu-accent`, `--wu-doux`, `--wu-bord`, `--wu-rayon`, `--wu-police`.
- `localStorage` key `whats-up:<app>` = last seen id; URL parameter `whats-up` = `apercu` | `revoir`; event `whats-up:vu` with `detail.id`; attribute `vu` read before `localStorage`.
- First visit (nothing seen): only the newest note.
- Guard message: `Pas de fiche What's up ? pour cette mise en prod : lance /whats-up, ou écris la raison.`; escapes: line `Sans nouveautés : <raison>` in a PR body, env `WHATSUP_SANS="<raison>"` for a push.
- Every tooling failure in a guard lets the push or PR through with a warning on stderr.
- Skill and docs text in French with accents; code comments in English, one line, the why.

## Review Focus

1. A push that deletes the prod branch or pushes a tag must not be judged (no note to read) → pass. Test in Task 1.
2. Ids with `-10` or more must sort after `-9` (string sort gets it wrong). Test in Task 1.
3. `gh pr create --base main --body "… --base main …"` without `--head`, from a feature branch: the head is the current branch, the quoted `--base` in the body is ignored. Test in Task 1.
4. `index.json` malformed or missing on what ships while present on prod → refuse (the note was lost), not crash. Test in Task 1.
5. A note whose CSS has `@import url(https://…)` or `background: url(//cdn…)` must lose them, while `url(data:…)` stays. Test in Task 3.

### Task 1: The guard `garde.py`

**Files:**
- Create: `plugins/osho-core/skills/whats-up/scripts/garde.py`
- Test: `plugins/osho-core/skills/whats-up/scripts/test_garde.py`

**Interfaces:**
- Produces (CLI, run from the repo root):
  - `python3 .whatsup/garde.py claude` — stdin = Claude hook JSON (`tool_input.command`); exit 0 pass, exit 2 refuse (message on stderr).
  - `python3 .whatsup/garde.py pre-push <remote> <url>` — stdin = git's pre-push lines; exit 0 pass, exit 1 refuse.
- Produces (functions, for tests):
  - `cle(id: str) -> tuple[str, int]`
  - `derniere(ids: list[str]) -> str` (`""` when empty)
  - `config(repo: str) -> dict | None` (reads `.whatsup/config.json`; None if absent or invalid)
  - `ids_sur(repo: str, ref: str, dossier: str) -> list[str] | None` (`git show <ref>:<dossier>/index.json` → `ids`; None if absent; raises `ValueError` if malformed)
  - `decider(part: list[str] | None, prod: list[str] | None) -> bool` (True = pass)
  - `pr_vers_prod(cmd: str, prod: str) -> str | None` (head branch name, or the current branch marker `""` when no `--head`; None when the command is not a PR to prod)
  - `echappe(cmd: str, corps_fichier: str = "") -> bool`
  - `poussees(lignes: str, prod: str) -> list[tuple[str, str]]` (`(local_sha, remote_sha)` for lines whose remote ref is `refs/heads/<prod>` and local sha is not all zeros)
- Line 2 of the file: `# whats-up garde v1` (the install compares it to update).

**Interfaces:**
- Produces: ES module; line 1 `// whats-up v1`; named exports `dues(ids: string[], vu: string | null): string[]`, `filtrerCss(css: string): string`, `cle(id: string): [string, number]`; defines custom element `whats-up` only when `customElements` exists (so node can import it).
- Element: attributes `src` (folder URL, trailing slash), `app`, `lang` (`fr` | `en`, default `fr`), `vu`; method `ouvrir()`; dispatches `whats-up:vu` (`bubbles`, `composed`) on close when it marked something seen.
- `dues`: `vu === null` → `[newest]`; else ids strictly newer than `vu`, oldest first; `[]` if none.
- `filtrerCss`: drop `@import …;` rules; replace `url(…)` whose target starts with a scheme (`http:`, `https:`, `//`, `javascript:`) by `none`; keep `url(data:…)` and relative URLs.
- HTML cleaning (browser only): parse with `<template>`; allowed tags `div span p b i strong em ul ol li br svg path line circle rect polyline g`; allowed attributes `class style aria-hidden` + SVG geometry (`d viewBox x y x1 y1 x2 y2 cx cy r width height points fill stroke stroke-width`); drop everything else, all `on*`, any `style` containing `url(` with a scheme; `texte` keeps only `b i br`.
- Labels: fr `Nouveautés de {app}`, `Précédent`, `Suivant`, `C’est parti`, `Fermer`, `{i} sur {n}`; en `What's new in {app}`, `Previous`, `Next`, `Let's go`, `Close`, `{i} of {n}`.
- Window: `role="dialog"`, `aria-modal="true"`, labelled by the title; focus moves in and is trapped, returns to the previous element on close; Escape closes; ArrowLeft/ArrowRight; dots per screen; scene area 340 px high, scene re-mounted per screen so animations replay; `prefers-reduced-motion: reduce` → `animation: none; transition: none`; width fits 390 px screens. Styles use only `var(--wu-*)` with sober fallbacks.
- Loading: fetch `src + "index.json"` then each due note (`<id>.json` + `<id>.css`); any failure → render nothing, no throw. `?whats-up=apercu` → newest, writes nothing; `?whats-up=revoir` or `ouvrir()` → newest, writes nothing.
- `apercu.html`: loads `./whats-up.js`, mounts `<whats-up src="./exemple/" app="Exemple">` and opens it in preview; `?src=<folder>` and `?theme=<css url>` override the folder and add a theme stylesheet; buttons to toggle light/dark background.
- Example: `2026-01-01` = a clean "tuto" note (2 screens, animated scene); `2026-01-02` = a trapped note (a `<script>`, an `onerror`, an `<img src=https://…>`, a CSS `@import url(https://…)`) that must render with all of them gone.
